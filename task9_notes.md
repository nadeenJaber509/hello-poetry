# Task 9 – Your First RAG Chatbot

## Step 2 – Building the RAG Function

### Implementation

Created `rag.py` with three functions:

- `format_sources()`: Formats retrieved chunks with numbered citations, titles, file names, and text.
- `build_messages()`: Builds the system prompt and user message containing the sources and question.
- `answer_question()`: Uses Hybrid Search to retrieve relevant chunks, sends them to the Groq model, and returns the answer, sources, and full prompt.

### First Test

**Question:** Which command creates a new Poetry project?

**Answer:** `poetry new my-package`

**Result:** Correct.

**Source verification:**

Source [1], `cli.md`, contains the `new` command and explains how it creates a new Poetry project.

**Observation:** The first source directly answered the question, while sources [2] and [3] were less relevant.

- **Model:** `openai/gpt-oss-20b`
- **Temperature:** 0
- **Retrieval method:** Hybrid Search
- **Number of retrieved chunks:** 3

### Second RAG Test

**Question:** How do I add a package using Poetry?

**Answer:** Use `poetry add <package-name>` to add a package to the project. You can also specify a version constraint.

**Result:** Correct.

**Source verification:**

- Source [2] (`cli.md`) directly explains the `poetry add` command.
- Source [1] (`basic-usage.md`) also discusses adding dependencies.
- Source [3] is less relevant because it explains `poetry self add`, which manages Poetry's own packages and plugins.

**Observation:** The RAG system retrieved relevant sources and generated a correct answer with a citation.

## Step 4 – Manual Evaluation

I manually evaluated the answers generated by the Plain LLM and RAG systems using three labels: Right, Partly, and Wrong.

| Metric | Plain LLM | RAG |
|---|---:|---:|
| Right | 19 | 28 |
| Partly | 5 | 2 |
| Wrong | 6 | 0 |

### Observations

- RAG produced more correct answers than the Plain LLM.
- RAG answered several questions correctly where the Plain LLM failed, such as the minimum Python version, installing all dependency groups, and project-specific plugins.
- Some answers were partially correct because they contained incomplete or inaccurate explanations.
- Retrieval hit rate and answer correctness are different metrics. A correct answer does not necessarily mean that the expected document was retrieved.
- Citation accuracy requires checking whether each numbered source actually supports the corresponding claim.

### Conclusion

RAG improved answer quality in this evaluation by using relevant documentation as context. However, some retrieval results and explanations still need improvement, especially for more complex questions involving build scripts and exclusive extras.

## Step 6 – Special Questions Evaluation

I tested the RAG chatbot using five special questions to evaluate its behavior when questions are unrelated to the documentation or require information that is not covered by the available sources.

### Results

| Question | Result |
|---|---|

### Observations

- The chatbot can reject unrelated questions.
- It can recognize when information is missing from the available documentation.
- It did not invent answers or provide unsupported deployment commands.
- The retriever still returned document chunks, even when the questions were unrelated or unsupported.
- Some retrieved sources were not relevant to the questions and did not support the chatbot's responses.

### Conclusion

All five questions received appropriately cautious answers based on the available documentation.

This experiment showed that RAG can reduce hallucinations, but retrieval alone does not guarantee that every answer is fully grounded in the provided documents. Retrieving sources does not necessarily mean that those sources are relevant or sufficient to answer the question.

## Step 6 – Testing the Two Unanswerable Questions from Task 8

I also tested the two questions marked as unanswerable (`answerable=no`) in the Task 8 `questions.csv` file.

### Question 1

**Question:** Does Poetry include a built-in graphical debugger for stepping through Python code?

**Chatbot answer:** The chatbot stated that the provided documentation does not contain information about a built-in graphical debugger in Poetry.

**Retrieved sources:**

- Source [1]: `building-extension-modules.md` – discusses building and distributing native extensions.
- Source [2]: `_index.md` – discusses Poetry installation methods.
- Source [3]: `cli.md` – discusses Poetry commands.

**Source verification:** No. These sources do not discuss graphical debugging or a built-in debugger.

**Observation:** The chatbot did not invent an answer, but the retrieved sources were unrelated to the question.

### Question 2

**Question:** Can Poetry install and manage Ruby gem dependencies using a Gemfile?

**Chatbot answer:** The chatbot stated that the documentation does not contain information about Poetry handling Ruby gem dependencies or using a Gemfile.

**Retrieved sources:**

- Source [1]: `basic-usage.md` – discusses Python project dependencies and adding packages.
- Source [2]: `cli.md` – explains the `poetry install` command.
- Source [3]: `basic-usage.md` – explains dependency installation and package repositories.

**Source verification:** No. These sources discuss Poetry's dependency management but do not explain Ruby gems or Gemfiles.

**Observation:** The chatbot correctly avoided inventing an answer, but the retrieved sources did not directly address the question.

### Main Observations

- The chatbot refused to answer both questions because the required information was not available in the documentation.
- The retrieved sources were related to Poetry in general, but they did not directly support the answers.
- The absence of information in the documentation does not prove that a feature does not exist.
- A citation is not automatically evidence that an answer is correct. The source content must actually support the answer.

### Conclusion

The two additional tests confirmed that the chatbot can avoid guessing when information is missing. However, the retrieval system sometimes returns general Poetry documentation that is not relevant to the specific question.

A better RAG system should evaluate the relevance of retrieved sources before using them as evidence. If no sufficiently relevant information is found, it should clearly explain that the available documentation does not provide an answer.

## Overall Task 9 Conclusion

Building the RAG chatbot improved answer quality compared with the Plain LLM in the manual evaluation. The chatbot also showed cautious behavior when answering questions that were unrelated to the documentation or not covered by the available sources.

However, the experiments revealed that retrieval quality and answer correctness are two different things. The system can retrieve document chunks without retrieving information that actually answers the question. Therefore, a reliable RAG chatbot should not only retrieve sources and generate answers, but also check whether the retrieved information is relevant and supports its claims.

The chatbot should clearly state when the documentation does not contain enough information instead of relying on unrelated sources or making unsupported claims.
